# 一步 · 目标太远，先做一步

1024 造物挑战参赛作品，单用户网页应用。纯静态、零依赖、零构建。

**同一份代码手机和桌面都长在合适的位置**：手机是底部 tab + 拇指区输入（做完当场勾）；桌面是左侧边栏 + 居中 760px 内容列（建目标、看流水）。

**是一个可安装的 PWA**：支持「添加到主屏幕」、离线打开、独立窗口运行。

设计依据：`sycamore/docs/1024-stepone-design.md`

仓库：<https://github.com/jiumigu/stepone>（MIT，欢迎拿走改成你自己的）

---

## 跑起来

```bash
cd stepone
python3 -m http.server 8080
# 打开 http://localhost:8080
```

必须走 http，不能直接双击 `index.html`：ES module 在 `file://` 下会被浏览器拦截。
直接双击时页面顶部会出现一行提示，但不影响看到静态样式。Service Worker 在 `file://` 下不会注册（没有 HTTPS/localhost 环境）。

```bash
node tools/smoke.mjs    # 42 项逻辑验收（mock localStorage，无需浏览器）
node tools/shot.mjs     # 注入演示数据 + 逐页截图（需本机 Chrome，开发自查用）
node tools/icon.mjs     # 重新生成 PWA 图标（改了主色或图形时跑）
```

截图脚本支持尺寸和桌面模式：

```bash
W=390  H=844             node tools/shot.mjs 9333   # 手机
W=1440 H=900 MOBILE=0    node tools/shot.mjs 9334   # 桌面
```

### 安装成 App

- **Chrome / Edge（桌面）**：地址栏右侧的安装图标，或菜单 →「安装一步」。
- **Safari（iOS）**：分享 →「添加到主屏幕」。
- **Chrome（Android）**：菜单 →「安装应用」。

装完之后没有地址栏、断网也能打开，数据仍然只在本机。

## 复用：改哪儿改什么

整个项目 22 个源文件、约 5,200 行（含样式与入口 HTML；另有 3 个验收脚本约 960 行），没有一行业务依赖框架。想改成自己的版本，通常只需要动这张表里的位置：

| 想改 | 改哪里 | 说明 |
|---|---|---|
| 主色 / 圆角 / 字体 | `src/style.css` 顶部 `:root` | 只有一处，改 `--brand` 全站跟着变 |
| 积分给多少 | `src/core/points.js` 的 `RULE` | 唯一汇率表，改数字即可，流水和余额自动跟着算 |
| 快乐几档、叫什么 | `points.js` 的 `JOY_BANDS` | 常量只写一处，弹窗和流水不会对不上 |
| 里程碑怎么排 | `core/goals.js` 的 `planMilestoneDates()` | 每天 / 每周 / 每月 / 一次性四种节奏，加一种在这里 |
| 里程碑叫什么 | `core/goals.js` 的 `milestoneTitle()` | 命名口径的唯一来源 |
| 加一类事件（比如「运动」） | `selectors.js` 的 `dayEventMap()` + 一张新表 | 见下方硬规则 5，漏了日历就查不到 |
| 换成云端存储 | `core/store.js` 的 `useAdapter()` | 实现 `{ name, read(), write() }` 即可，业务层不动 |
| 加一个页面 | `index.html` 加 `<section data-page>` + `src/ui/xxx.js` 导出 `mount/update` | 路由在 `app.js` 的 `PAGES` |

改之前先读下面七条硬规则 —— 它们不是风格偏好，是「余额和进度不会算错」的前提。

## 数据

全部存在 `localStorage` 的 `stepone.v1` 一个 key 里，8 张表：
`goal / milestone / todo / routine / joy_log / point_txn / gift / setting`。

`schema_version` 现在是 **2**。老存档（v1）第一次被读到时自动补出 `routine` 表和 `setting.roll_date`，
补完立即落盘 —— 迁移只做「缺什么补什么」，不删任何已有字段。

### 导出与恢复（界面里的入口）

**银行页最底部 →「备份与恢复」**，桌面端也可以点左栏底部那两行小字。

- 导出：下载 `stepone-backup-YYYY-MM-DD.json`，里面是完整的一份存档；导出时间会记在 `setting.last_export_at`。
- 恢复：选文件 → 校验形状 → 二次确认 → 整份替换。**不像备份的文件会被拒绝**，不会因为点错文件把现有数据洗成空白。

为什么把它放在这么显眼的位置：数据只在 localStorage，换设备、清缓存、换浏览器都会丢，这是唯一的安全出口。
控制台仍然可用（`localStorage.removeItem('stepone.v1')` 清空、`exportJSON()` 取全文），但那是备用通道。

## 日历上看到的到底是什么

一格里的点是**那天真实发生的事**，不只是待办：

| 颜色 | 来源 | 记在哪一天 |
|---|---|---|
| 橙 | 待办 | 完成了记「做完那天」，没完成记「计划那天」 |
| 蓝 | 里程碑 | 同上 |
| 绿 | 快乐记录 | 记录产生的那天 |

实心＝那天做成了，空心＝那天只是安排着。计划日与完成日不同的条目会**两处各留一条**
（11/1 该交这一步、10/22 真的做了），这样才能回答「我在哪天做成了它」；
同一天既计划又完成只留一条，不重复计数。

计划日那一条如果后来被做掉了，标题同样会划掉，但勾选框保持空心、只留一个淡勾 ——
**圈没填实＝不是这天做的**。点它不会没反应，会告诉你「10月22日 已经做过了」。

点开某一天，抽屉按「待办 / 里程碑 / 快乐」分组。里程碑可以在抽屉里直接完成或撤销，
和其它入口走同一个 `completeMilestone()`。

## 里程碑叫什么

周期性的目标（每天 / 每周 / 每月）自动生成的里程碑，名字是
**目标名的前 10 个字 + `· 第 N 天 / 周 / 个月`**，例如「背单词 · 第 3 天」。

不是为了好看：里程碑会单独出现在日历抽屉、今天页、目标卡片上，那些位置只有它自己，
「第 3 天」三个字认不出是哪件事。带上目标前缀，它走到哪儿都自解释。

- 已有目标的裸名字（「第 1 个月」）不会自动改 —— 目标详情右上角 `···` →「里程碑名字补上目标名」，
  只补完全匹配自动命名格式的，**手改过的名字一律不动**，重复点也不会重复加。
- 自动命名只是默认值，之后逐个改名不受影响。


## 里程碑的「完成感受」在哪填

只在**完成这一步的时候**填，和 `done_at` 写在同一事务里 —— 所以不存在「感受写了、状态还是没完成」的中间态。

编辑表单里只有「名称 / 计划日期」；已经完成的里程碑才多出一个「当时的感受」可以补改。

## 「加一步」和「加一件」是两个东西

界面上有两个长得像的动作，写入的是两张表，别混：

| 入口 | 写什么 | 出现在哪 | 完成给几分 | 动进度吗 |
|---|---|---|---|---|
| 目标详情 →「加一步」 | `milestone` 表 | 目标时间轴、日历 | +10 | **会** |
| 今天页 →「从目标里挑一步」/ 底部输入框 | `todo` 表 | 今天页、日历 | +2 | **不会** |

目标详情那个按钮的 hint 写着「完成后算进目标进度」，所以它必须写里程碑；
写成待办的话，用户会看到「加了一步，目标里却没有它，只在日历里看得见」。

新建的里程碑会**滚到视野中央并闪一下**，不然列表长了以后，加完仍然像是没生效。

## 抽屉在桌面端是居中面板，不是贴底蕴

手机上是底部抽屉（拇指够得着），桌面端同一个组件换形态：居中、560px 宽、上下留白各 256px 左右。
不是为了好看 —— 原生日历弹层约 300px 高，塞进一个贴底、只有 260px 高的抽屉里只能往上顶，
会压住标题和「加进去」按钮（真实截图）。抽屉居中之后弹层有地方展开，日期框也从 420×44 变成 512×46。

另外日期框下面给了「今天 / 明天 / 目标截止日」三个快捷键：多数情况根本不用打开原生日历。

## 重复任务的行为约定

「每天 / 工作日 / 每周一·三·五」三种规则，到点自动出现在「今天」。

- **只补今天，不补历史**。App 关了五天再打开，只出现今天这一条，不会冒出五条逾期红字。
  代价是那五天的日历格子是空的 —— 这是刻意的，和「断一天不惩罚」是同一条立场。
- **生成幂等**：同一规则同一天最多一条待办，反复启动、跨过午夜、多标签页同时跑都不会重复。
- **完成不加新通道**：实例就是普通待办，仍然只走 `completeTodo()`（+2）。
- **删掉实例 = 今天不做**：记进 `skip_dates`，当天不再重建，明天照常。
- **删掉规则**：今天未完成的实例一起清掉，已完成的保留（历史不能被抹掉）。

## 七条不可违反的规则（改代码前先读）

1. **完成只走 `completeTodo()`**，`done_at` 非空即返回，不加分。日历抽屉、目标详情、重复任务实例也必须调它。
2. **积分只走 `pushTxn()`**，且必须在 `commit(mutator)` 内部调用。没有、也不应该有「手动加分」按钮。
3. **进度不手填**。`goal.progress` 是 `recalcGoal()` 算出来的派生值，UI 只读。
4. **状态只在 `commit()` 里改**。UI 层、`noteSkip` 之类的工具函数都不许直接写 `getState()` 返回的对象。
5. **界面上出现过的记录，日历必须查得到**。新增一类事件（待办 / 里程碑 / 快乐之外）时，
   必须同时在 `selectors.dayEventMap()` 里登记归属日期，否则它会成为「只在某个页面活一次」的孤岛。
6. **自动生成的名字要自带上下文**。一条记录会离开它出生的页面（里程碑会进日历、今天页、流水），
   名字里必须能独立认出来源 —— 不能只叫「第 3 天」。同一份文案只有一个来源：`core/goals.js` 的
   `milestoneTitle()`。
7. **同一个动作只有一种语义**。「目标里的加一步」只写 `milestone`，不写 `todo`；
   界面上叫「加一步」，写入端就必须是 `addMilestone()`。反例：曾经这个按钮按 `goal_id` 写了一条待办 ——
   它出现在今天页和日历里，却永远不进目标时间轴、不动进度，用户看到的就是「加了但列表里没有」。
